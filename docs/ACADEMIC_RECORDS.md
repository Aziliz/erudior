# Local academic records and portability

Open **Family / Classroom → Academic records** after the existing adult gate. Select the learner before editing. This is a local planning tool, not a legal graduation determination, accredited transcript, institutional transfer-credit verification or credential issuer.

The public website remains account-free and does not enable local Family/Classroom management. Opening `/parent/academic-records` there shows an explicit local-app availability screen, not a learner editor or a silently substituted Library. In a supported local app without a workspace, the same entry offers existing workspace setup; configured workspaces still require the adult gate. Temporary guest sessions do not create persistent workspaces. Native source ships with the next app version, not automatically with a website deployment.

## Planning and review

Configure your own total-credit goal and subject requirements; no state or jurisdiction is preselected. A subject can require an evidence description. Existing completed local course records contribute to the plan; parent-entered outside coursework needs explicit review. Add supplemental transfer/local statements, review them, correct them or remove them. Linking a correction to an existing source replaces its planning contribution rather than counting twice; the original transcript and course grades are not changed. Evidence descriptions and parent review do not authenticate an institution or issuer.

## Portable records

Preview a bounded JSON export containing policy, credit statements and historical attendance, manual learning, parent-grade, reading, activity and evaluation summaries. Raw answers, account/profile identifiers and attachment files are excluded automatically. Free text can contain names and sensitive information: inspect the preview and share intentionally. Existing Reports provide printable report cards/transcripts/portfolios; Settings and backup provides full device recovery.

Imports are previewed before saving and append unverified, unreviewed statements with retained provenance. They do not replace the destination policy, identity, progress, gradebook or official credit. Duplicate packages/sources are rejected; correct the existing entry instead. Historical summaries remain read-only and retain their provenance across subsequent exports. JSON checksums are duplicate detection, not signatures or trust. No upload or account is required.

## Persistence and recovery

Records use compare-and-swap revisions. A timer, reader or another tab cannot silently overwrite a stale parent editor; reload the latest records and reapply the intended change. Captured learner guards prevent a delayed callback from writing into a newly selected profile. Deleted learner IDs cannot be recreated by stale writes or backup restore. Damaged stored records are quarantined in place, not replaced by an empty fallback; download the original recovery copy and restore a valid backup intentionally.

The local audit records changed field names, time, revision and action, retaining the latest 1,000 entries. It is a bounded, editable-device log, not tamper-proof institutional evidence. Restored history is identified as imported. Plain and encrypted backups preserve the new data; restore demotes imported planning claims to unreviewed. Full-family backup restore spans multiple files and is not an atomic transaction; interrupted restores can require retry/recovery.

## Retention and authorization boundaries

There is no automatic deletion. Choose a cutoff, inspect selected supplemental planning entries, then explicitly confirm or cancel local cleanup. Existing attendance, transcript records, documents, audit and import archives remain. Downloaded exports, backups and other devices are not deleted by this operation. Wider deletion uses the existing Learner privacy workflow.

Authorization remains the existing local adult gate and learner scope. Managed online sign-in, institutional custody/holds, guardian verification, server retention jobs and cross-device synchronization belong to the separate account integration work. This feature adds no production identity provider, external learner-data collection, new course signing authority or private curriculum changes. Native source can ship with the next app version; this work does not itself issue an installer release.
